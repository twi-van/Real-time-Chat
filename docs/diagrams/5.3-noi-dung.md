# 5.3. Sơ đồ Sequence diagram

Mục này mô tả thứ tự tương tác theo thời gian giữa **Client A**, **Client B**, **Backend** (Express + Socket.io) và **Database** (PostgreSQL / Prisma). Chi tiết payload xem mục 5.2. Mỗi tiểu mục kèm một hình sequence tương ứng trong thư mục `docs/diagrams/`.

---

## 5.3.1. Đăng nhập, kết nối Socket và presence

1. Client A gọi `POST /auth/login` → Backend kiểm tra DB → trả `{ user, token }`.
2. Client A mở Socket.io kèm `auth: { token }`.
3. Backend verify JWT (+ rate limit connect); sai → `connect_error` / `UNAUTHORIZED`.
4. Hợp lệ → hoàn tất connection; socket được `join` kênh `user:{userId}` (để nhận tin đẩy theo user); đánh dấu online.
5. Backend phát `presence` online (snapshot cho A; thông báo A online tới các client khác, ví dụ B).

**Ý nghĩa:** REST cấp phiên; Socket tạo kênh realtime. Kênh `user:{id}` bổ sung cho việc nhận `receive_message` kể cả khi chưa `join_room` đúng phòng chat đang xem.

*(Hình: `5.3.1-login-connect.png`)*

---

## 5.3.2. Mở danh sách room, lịch sử tin và `join_room`

1. Client A gọi `GET /rooms` (JWT) → Backend trả `rooms[]` kèm `lastMessage?`, **đã sắp xếp theo hoạt động mới nhất**.
2. Khi chọn một room: `GET /rooms/:id/messages` → kiểm tra member → trả lịch sử (+ cursor).
3. Client A `emit("join_room", { roomId })` → Backend kiểm tra membership → `socket.join(roomId)` → ack.

**Ý nghĩa:** REST tải nền (list + lịch sử). `join_room` đăng ký phòng Socket để **được gửi tin / typing** trong room đó.

*(Hình: `5.3.2-open-room.png`)*

---

## 5.3.3. Gửi và nhận tin nhắn realtime

Giả sử A và B đã connect (đã ở kênh `user:…`); A đã `join_room` R để gửi.

1. A `emit("send_message", { roomId, content }, ack)`.
2. Backend: validate → rate limit → member + đã join R.
3. Lỗi → ack `VALIDATION_ERROR` / `RATE_LIMITED` / `FORBIDDEN` (không ghi DB).
4. Hợp lệ → lấy danh sách member → `INSERT` tin → tạo object tin.
5. Backend `emit("receive_message", tin)` tới từng `user:{memberId}` (A và B đều nhận nếu đang connect).
6. Ack `{ ok: true, message }` cho A.
7. B có thể đang xem phòng khác vẫn nhận tin → UI cập nhật sidebar / unread (phía FE).

**Ý nghĩa:** Lưu DB + server push. Broadcast theo kênh user thay cho chỉ `io.to(roomId)`, hỗ trợ UX danh sách hội thoại realtime.

*(Hình: `5.3.3-send-message.png`)*

---

## 5.3.4. Typing indicator

1. A (đã join R) `emit("typing", { roomId, isTyping: true })`.
2. Backend kiểm tra member + đã join → `socket.to(roomId).emit("typing", …)` tới socket khác trong room.
3. B hiện “A đang nhập…”; khi `isTyping: false` thì ẩn.
4. Typing **không** lưu Database.

**Ý nghĩa:** Tín hiệu tạm thời; vẫn gắn phạm vi **room Socket** (cần `join_room`).

*(Hình: `5.3.4-typing.png`)*

---

## 5.3.5. Ngắt kết nối và presence offline

1. A disconnect (đóng tab / mất mạng).
2. Backend gỡ `socketId` khỏi tập online của A.
3. Còn tab khác → không phát offline.
4. Hết mọi socket của A → `presence` `{ status: "offline" }` tới các client (ví dụ B).

*(Hình: `5.3.5-disconnect.png`)*
